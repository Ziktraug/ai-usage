## Product outcome

A request keeps its identity when unrelated activity follows it. Work can
qualify and start a read-only Codex review of one declared checkout and fixed
commit, retain the native execution identity and return to its result. Codex
attention uses only attributable native evidence. A project's bounded context
is reachable independently of other projects' page occupancy.

The coordinator owns shared contracts, store schema, integration and final
verification. Parallel authors use separate worktrees. Full gates and browser
runs are serialized. Only disposable stores are opened by the modified engine.

## Acceptance

- Chronology, lineage and an unrelated pull request cannot settle a request.
  Explicitly attributable native responses affect only their own question.
- A qualified Codex recommendation is executable from Work with a fixed bounded
  patch, an observed subscription account, the chosen model and no API fallback.
- Concurrent launch requests and lost contact preserve one durable reservation.
  Stop requested and native interruption confirmed are separate observations.
- The asynchronous input tool's immediate `accepted` response is not a human
  response. Missing evidence remains unknown, including after process exit.
- Scope precedes read limits; historical exploration is explicit and bounded.
  CLI, MCP and browser retain the same provenance and coverage semantics.
- A real browser path reaches Codex on an authorized disposable target, or the
  precise external block remains documented without claiming mock proof as live.
