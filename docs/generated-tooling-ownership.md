# Generated Tooling Ownership

This repo uses generated files from PandaCSS, SvelteKit, Vite, the selected Bun
adapter, and Turborepo. The ownership rules are:

## Tracked Inputs

- `apps/web/src/routes/` is ordinary tracked SvelteKit route source; no generated
  route tree is committed.
- Panda configuration and package exports are tracked inputs to code generation.
- `panda lib` owns the generated `styled-system` subpaths in
  `packages/design-system/package.json` exports (`./css`, `./css/*`,
  `./patterns`, `./patterns/*`, `./tokens`, `./helpers`, `./types`, and
  `./panda/*`) and rewrites them on every design-system build. The other
  exports stay hand-written. Commit the synced `package.json`; a build that
  changes it means the generated shape changed.

## Ignored Generated Directories

- `styled-system/` is generated by PandaCSS in `@ai-usage/design-system` and
  `@ai-usage/web`. In the design system it also holds `styled-system/panda/`,
  the `panda lib` manifest (`lib.json`, `preset.mjs`, `buildinfo.json`) that
  `apps/web/panda.config.ts` consumes through `designSystem`.
- `apps/web/.svelte-kit/` contains phase-isolated SvelteKit intermediates.
- `apps/web/.output-build/` contains the Bun production adapter output and the
  short-lived production-build lock.
- `.turbo/` is Turborepo cache state.

## SvelteKit Outputs

- `apps/web/.svelte-kit/check`, `apps/web/.svelte-kit/dev`, and
  `apps/web/.svelte-kit/build` are separate check, development, and production
  intermediate trees.
- Each command sets `AI_USAGE_SVELTEKIT_PHASE` and owns only its matching phase.
- SvelteKit 3 also writes `apps/web/node_modules/$app/` (the `$app/tsconfig`
  parent configuration and the `$app/types` declarations). Every phase rewrites
  that one directory, so `apps/web/tsconfig.json` pins `rootDirs` to the check
  phase's route types; type-checking never depends on which phase synced last.
- Non-production adapter scratch output stays below its phase intermediate tree.
- The production client build writes its private module-graph manifest to
  `apps/web/.svelte-kit/build/private/client-modules.json`; the fail-closed
  scanner consumes it before the generated tree is discarded.
- The production Bun adapter writes only `apps/web/.output-build/sveltekit/`.
  Its generated hand-off module is kept as `adapter-bun.generated.js` behind the
  `adapter-bun.js` module that binds the runtime origin (ADR 0057).
- `apps/web/.output-build/build.lock` serializes production builders. The build
  wrapper validates the private container before deleting only the canonical
  production adapter and production intermediate children.
- Generated trees are disposable, untracked, excluded from recursive scanners,
  and must never be hand-edited or committed.

## Turbo Outputs

- `@ai-usage/design-system#build` and `@ai-usage/design-system#check` cache
  `styled-system/**`.
- `@ai-usage/web#build` declares `.output-build/sveltekit/**` and
  `styled-system/**` as final outputs, but caching is disabled for that task.
  Every root build enters the production-build lock; a cache restore cannot
  mutate adapter output around the lock.
- `@ai-usage/web#check` caches `styled-system/**` from Panda codegen/cssgen.

## Direct Package Scripts

`apps/web` scripts still run `bun --filter @ai-usage/design-system build` before Panda commands. This is intentional because developers and tests run package scripts directly, outside `turbo run`, and the report Panda scan loads the design system's `panda lib` manifest (`@ai-usage/design-system/panda/lib.json`) through `designSystem`: it merges the design-system preset and replays the styles extracted from design-system source instead of scanning that source again. Without a current manifest the web Panda commands fail with a `design_system_*` diagnostic, or warn with `design_system_buildinfo_stale` and re-extract the design-system source.

Panda commands run as `bun --bun panda …` so they work without a `node` binary on `PATH`, and use `--log-level warn`, because `--log-level silent` would also hide the diagnostic that explains a failing exit code. The web Panda run currently prints `panda_call_unextractable` warnings for `css()` merges whose base is a design-system style object (Panda 2 does not follow imports into the design-system package). They are expected: those atoms come from the design system's build info and the app's own `css.raw()` overrides, so no CSS is missing.
